Silence isn't proof of AI.

Every AI-attribution tool built on top of an editor uses the same shortcut: if a line changed and nobody saw you type it, call it AI. That's a guess dressed up as a signal — a formatter, another agent, a Git operation, or a teammate's Live Share session all look identical to "the AI did it" under that logic.

Tourist adds a third, honest state: external / unknown. If it can't trace a change back to a real Claude Code signal, it says so — instead of quietly marking your commit history with a confident answer it has no basis for.

How it works

Three tiers of evidence, checked in order.

Tourist doesn't classify a line until it has run out of stronger evidence to check first. Each tier only fires when the one before it comes up empty.

TIER 1
Did Claude Code's own hook report writing this line?

Tourist installs a hook into Claude Code's PreToolUse/PostToolUse events for Edit, Write, and MultiEdit. This is ground truth, not inference — Claude Code told Tourist directly.

Yes → AI No → check Tier 2
TIER 2
Was the file clean, and does the disk write line up with an active Claude Code IDE session for this workspace?

Corroborating evidence — Claude Code's own IDE lock file, or a shell/process trail — for a hook signal that didn't arrive. Lower confidence than Tier 1, but still tied to a real, observable Claude Code session, not a guess.

Yes → AI (corroborated) File was already dirty → Human Neither → check Tier 3
TIER 3
No hook signal, no corroboration — what actually changed this line?

A formatter, another tool, another AI, a Git operation, or anything else Tourist has no evidence about. This is the deliberate honest-uncertainty bucket. It is never collapsed into "AI" by default.

No evidence → External / unknown
Features

What you actually see while you work.

No dashboards to open, no reports to generate — attribution renders inline, live, in the editor you're already using.

Gutter decorations

Every attributed line gets a colored left-edge marker: solid blue for AI, solid orange for human, dashed magenta with a ? icon for external/unknown. Hover any line for a plain-language tooltip. Decorations update live as you type, save, and switch editors. Lines nobody has touched yet stay undecorated.

Status bar rollup

A status bar item shows your workspace-wide split as a percentage — e.g. Tourist: 40% AI, 45% human, 15% external. Click it to open the full breakdown.

Attribution tree view

A tree view named Attribution, nested under the built-in Explorer panel, rolls up stats folder → file — so you can see at a glance which parts of the workspace are mostly AI-written, human-written, or unknown.

Hook install & verify

Tourist: Install Claude Code Hook wires up the ground-truth signal in one step; Tourist: Verify Claude Code Hook confirms it's pointed at the right script. Both live in the Command Palette or the telescope icon in the editor title bar.

Toggle tracking & markers independently

Turn recording off and existing markers freeze in place — nothing new is saved. Turn gutter markers off separately to hide the visuals without touching what's being recorded.

Rename-safe history

Attribution is keyed by content hash, not file path, so moving or renaming a file doesn't orphan its history. Writes to local storage are atomic.

Persistence

Local by default. Shared only if you turn it on.

Tourist never phones anything home on its own. There are exactly two places attribution history can live.

Default · always on

Local storage

Every workspace's attribution history is written to a JSON file in VS Code's global storage, keyed by repo path and branch.

  • Zero configuration, zero network calls
  • Keyed by content hash, so renames don't orphan history
  • Writes are atomic
Opt-in · off by default

Git notes (team sharing)

Set tourist.gitNotesSync to true to sync attribution history as git notes under refs/notes/tourist-attribution, so a team can share it.

  • Sync is entirely manual — Push Attribution Notes / Fetch Attribution Notes
  • No automatic sync on commit
  • Nothing goes over the network unless you run one of those two commands with the setting enabled
A separate, opt-in feature

Knowledge Map: what you actually understand — not just what AI wrote for you.

Attribution tells you who typed a line. Knowledge Map answers a different question: given your real commits and diffs, what topics and skills does the evidence actually support? It's a separate system from the blue/orange/magenta line attribution above — deliberately not colored the same way, because it isn't gutter data.

Running it sends recent git diffs and commit messages to Claude to classify into three forests — Tech Stacks, CS Fundamentals, and Engineering Practice. Claude Code prompt history is only included if you separately opt into that as well.

Off by default. Nothing runs without explicit confirmation. Turn on tourist.knowledgeMap.enabled, then the first run shows a modal naming exactly what's about to be sent and which backend it's going to, before anything leaves your machine. Tourist: Generate Knowledge Map and Tourist: Show Knowledge Map are the two commands involved.

Use cases

Who this is actually for.

Tourist is scoped narrowly on purpose — one AI tool, one editor — in exchange for an honest signal instead of a confident guess.

Individual developers

Know your own AI usage, honestly.

See exactly how much of what's in your workspace you actually typed versus how much Claude Code wrote — without a tool inflating the "AI" number by lumping in every formatter pass and git checkout along the way.

Teams & reviewers

Accountability and audit trails on AI-assisted code.

Turn on tourist.gitNotesSync to share attribution history with teammates via git notes, so review focus and audit questions about AI-assisted changes are backed by ground-truth hook data — not a reviewer's memory or a guess about who touched what.

Engineering leads

See skill growth, not just AI-vs-human ratios.

Knowledge Map turns real commits and diffs into a picture of what a developer actually understands across tech stack, CS fundamentals, and engineering practice — evidence-based, and opt-in with explicit consent before anything is sent anywhere.

Learning & onboarding

Tell AI-authored scaffolding apart from what you wrote to learn it.

When you're ramping up in a new codebase alongside Claude Code, the gutter tells you at a glance which lines you should actually be able to explain — and which were generated for you.

Tourist is a VS Code extension you build and load locally — clone it, install dependencies, and launch an Extension Development Host.
